# Bounded PoC generator interface

Proposal for POC-1..3 at accepted base `439ebaa298882777a1f11b2573b689c42cd7e6fe`.
PR20's amendment and exact-head independent review (`ce278c4`, base `0e1a11`; review blob `2019b3d016a3782093b75a47d4a065b204d0566c`) are present after merge; the entry point, amendment and POC-VAL agree that panel/advance precedes fitting. Their resulting accepted tree is the assigned base. No statistical completion is implied.

The existing service owns accounts, clocks, approval, event storage and observed projection. A separate private generator image contains the restricted law and returns only typed observed records. It has no service database mount and no host port. The service/learner images contain neither generator source nor private trajectories. No new schema version is needed: panel identity/seed/index/day/action schedule are ordinary observable `patients.state_json` metadata; existing records cover patient, assignment, delivery, daily report and ISI. The generator is deterministic/stateless, replaying at most 98 days from seed and declared action history per call. Service errors/rollback leave the clock unchanged.

Replay seed/index are account-owned service/UI metadata only, **excluded from learner jobs, inputs and observed exports** because they reconstruct latent draws. Learners receive only the existing approved typed observed projection at its cutoff, never `state_json` or panel-generation receipts. Only the service may call generator RPC; the learner runs with network denied, no generator source and no generator/private-data mount. Implementation acceptance includes an actual copied-image role/access probe. Future evaluator access is a separate privileged role, not learner access.

Internal request: `{seed: integer 0..2147483647, index: integer 0..23, patient_id, through_day: 0..84, actions: [{day: 0..83, option: behavioral_continue|behavioral_escalate, assignment_id}]}`. Response: generated fictional name plus observed records (baseline patient and ISI, daily reports including explicit missingness, assignments' daily delivery/adherence, scheduled ISI). No latent states, response parameters or evaluator truth leave the generator. The service admits only the requested patient's records in the committed day range. Actions become effective on the next simulated night after explicit approval; day-14 assessments cover exactly days1..14. Public day0 cutoff is fixed `2026-01-01T12:00Z`; event availability is one minute before each daily cutoff. HTTP receipt time remains real; simulation event times are explicitly fictional.

Concrete clocks: domain cutoff on day d is January1 noon UTC + d days. An approval at noon day d becomes effective at20:00 that evening, before the overnight response indexed t=d+1. Each daily delivery/adherence event for night t is at20:00 on day t-1, after that day's noon decision and before the modeled overnight response; report and ISI event/recorded/available times are11:59 on day t, strictly before its noon cutoff. ISI recall end is11:00 that day, start exactly14 days earlier. The daily burden indexed t describes the preceding night, so day14 recall covers nights1..14; baseline day0 recall covers nights-13..0. For generated patients, existing approval and transition mutations preserve simulation/panel metadata; approval atomically appends its action change point and the ordinary assignment record. Decisions, follow-up validation and later-outcome projections use the patient-domain clock. Authentication, session expiry, operational safety receipt/audit times use the real clock; legacy patients retain existing clock behavior. A single small patient-clock helper suffices. Advance atomically commits records, metadata/day, versions, new decision and idempotency receipt, or rolls all back. Current hold/death guards block advancement/approval, historical views remain read-only, and no post-death outcomes are admitted.

Public authenticated/CSRF routes: `POST /api/panels/generate` `{seed,count}` returns generated panel IDs (new generation retained alongside prior patients); `POST /api/patients/{id}/advance` `{expected_version, mode: day|visit}` atomically advances one day or next multiple of14, capped84. Both use existing idempotency receipts. `GET /api/patients` includes generated groups; current workspace includes observable simulation day, seed, horizon, action schedule and timeline from existing events. Historical displays remain frozen. Ownership, stale checks, hold/death blocking and cutoff projections apply. Research consent is not invented: these are ordinary-care choices only; future randomized components require their existing consent checks.

Restricted law v1, frozen before truth/analysis: keyed SHA256 uniforms and Box-Muller normals keyed by seed/index/day/process, stable streams independent of action. Patient baseline severity `b=16+6U`, response multiplier `r=.8+.4U`, adherence probability `.85`, missing-report probability `.1`. Daily insomnia burden `z_t=b+.55 sin(2pi*t/21)+e_t-2r*C_t-4r*E_t`, with `e_t=.55e_(t-1)+.8N_t`, `C_t=.65C_(t-1)+.35*adherent_continue_t`, `E_t=.8E_(t-1)+.2*adherent_escalate_t`; baseline/premonitoring uses no action. Sleep quality `clip(10-z_t/3+0.45N,0,10)`, function `clip(9-z_t/4+.5N,0,10)`, diary minutes `clip(470-8z_t+20N,0,1440)`. ISI at day0,14,..84 is rounded/clipped mean burden over the complete preceding14 nights plus independent `N(0,1)` measurement noise, partitioned deterministically into seven 0..4 items. Daily reports are distinct one-night measurements; no wearable claims. Fixed support is no prompt. Behavioral escalation represents a stronger durable behavioral program with retained exposure, not a reversible medication or randomized escalation. No real efficacy interpretation. Future visit fitting must model these restricted observations and a compatible synthetic behavioral external contrast. N-of-1/MRT require a separately reviewed extension; they are not claimed here.

Initialize `e_-14=C_-14=E_-14=0`; execute14 untreated premonitoring nights indexed-13..0, then days1..84. Action entries are change points: the most recent approved plan with `action.day < t` persists for night t until replaced. No plan means zero new exposure. The service rejects a second approval on the same simulated day, including after manual prerequisite review; the generator requires strictly increasing action days. A missed adherence draw sets only that night's new treatment input to zero; both retained exposures continue decaying at their declared rates. Thus switching does not erase durable prior exposure. Uniforms use the first53 bits of SHA256 plus half a unit, divided by2^53; normals use separately keyed Box-Muller uniforms. Exact pinned-runtime replay, prefix equivalence and matched-seed branch tests qualify the implementation; no truth/fit result is supplied here.
