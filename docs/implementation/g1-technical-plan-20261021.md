## 2. Foundation: durable local service and security boundary

**Selected architecture:** one FastAPI service, React/TypeScript static client, and SQLite database on a local named volume. Use Python's SQLite driver and explicit SQL migrations; no ORM/event-bus/distributed cache framework. WAL, foreign keys enabled on every connection, `synchronous=FULL`, bounded busy timeout, explicit `BEGIN IMMEDIATE` for mutations. Single API process initially; separate connections for concurrent-request tests. No network-filesystem database. DuckDB/Parquet is analytical storage only, never the authority for consent, approval, session or event transactions. Integration Sol must qualify/pin the actual SQLite/Python build, FastAPI/Starlette, client toolchain, Argon2 implementation and analytical readers before their first source consumer; this plan is not release qualification.

Integration Sol owns root manifests/locks/configuration, container definitions, generated clients/shared schemas and migration numbering. Use the accepted G0-LIB lock once accepted; the inspected candidate pins NumPy 2.5.4, SciPy 1.18.1 and Pydantic 2.14.1, which are **pending inputs**, not permission to silently adopt them. Add only the shell/runtime dependencies required here. Record release/license/runtime/API checks and rejected combinations. Build images from pinned runtime digests; native Windows execution may be a development convenience, but acceptance uses the isolated Linux-container runtime below. Do not claim that Docker availability or volume permissions have already been verified.

### Persistence and replay

Create small tables for accounts/sessions, patient ownership/current version pointers, immutable event envelopes, immutable decision bundles, idempotency receipts and durable pending work. Event rows preserve canonical typed payload bytes/hash, raw source bytes/hash, record ID, patient ID, kind, lineage/revision, supersedes/duplicate/retraction headers, event/recorded/available timestamps and source/adapter version. Unique constraints cover record ID and original lineage/revision. Repeated transport delivery with the same idempotency key and payload returns the stored receipt; changed payload under that key conflicts. A distinct source duplicate is retained as a typed duplicate event pointing to the earlier original. Missing predecessor or invalid correction goes to a rejected-ingestion receipt; never guess a predecessor or silently replace a value.

Persist complete `ObservedHistory` lineage; only `ObservedHistory.project(cutoff)` produces learner values plus permitted provenance headers. Apply event <= cutoff and recorded/available < cutoff, then resolve visible lineage heads. Do not resolve the newest head globally before filtering: that would let a future correction erase yesterday's evidence. Validate no post-death symptom records, nested covariate timing, units, ISI version/recall and patient identity. Preserve local timezone/calendar/overnight episode data while storing ordering instants in UTC; test DST and cross-midnight boundaries. Ambiguous/naive input dates fail with a specific adapter error.

Replay uses a persisted run ID, source hash and cursor ordered by UTC availability, accepted temporal phase and stable record ID. Validate and commit the event batch, affected current-state/version pointers, pending-work row and replay cursor in one transaction. A crash before commit replays safely; after commit the receipt/cursor prevents duplication. Read current workspace under a consistent read transaction. Reconstruct from source order or reversed source delivery and obtain identical canonical state/snapshot hashes; wall-clock timing and database row order cannot alter clinical chronology. For live ingest retain actual receipt timestamps; replay must use declared synthetic availability, never backdate a live receipt.

An immutable decision bundle wraps the accepted `DecisionSnapshot` with exact referenced event/provenance hashes, eligibility reasons, saved recommendation/diagnostic payload, posterior/draw reference when present, evidence/prior/feature/model/policy versions, contemporaneous clinical/learning state, consent, follow-up and audit references. This is service persistence composition, not an unreviewed change to the domain schema. Hash and store the actual display payload; history reads it without invoking today's model or recomputing eligibility. Enforce no UPDATE/DELETE on immutable tables with database triggers and expose no historical mutation route. Current pointers can advance. Corrections/addenda/amendments append new events/bundles. Later outcomes require a separate authorized request and separate UI section.

For an ordinary synthetic approval, acquire the write transaction, resolve authenticated owner, reload current patient/state/consent/eligibility versions and holds, call accepted boundary validation, append approval/plan/follow-up/audit, advance versions and save idempotent response atomically. Failure rolls back all writes. Stale versions return a conflict with refresh reason; historical context is rejected server-side even with a forged current-mode field. Repeated successful key returns the same result; a new key against the stale version conflicts. Session revocation and current safety state are checked in this same admission boundary. No full model fit runs in a request transaction. Randomization engines stay gated to G3/G4: foundation preserves consent/approval contracts and explicitly rejects unavailable engine actions rather than fabricating assignments.

### Authentication and actual access controls

Administrative CLI seeds two synthetic doctor accounts with disjoint panels, one owner per patient; no public registration or account switcher. Use maintained Argon2 password hashing (candidate `argon2-cffi`, exact release qualified by integration), Python `secrets` for 256-bit opaque session tokens, and server-stored token hashes. Use HttpOnly cookies, Secure outside loopback, SameSite=Lax, fixed expiry/revocation and generic login errors. Session-bound synchronizer CSRF token plus same-origin checks protect every mutation including login/logout; use standard constant-time comparison. Rate-limit login by account and source with bounded stored attempt windows. Password reset revokes all account sessions atomically. Numeric expiry/rate settings are named, versioned demo configuration fixed by integration before tests; no security claim follows from their values.

Every patient, nested event, history, task, aggregate, draft and job-result route joins ownership to the authenticated session. Client-supplied doctor IDs are ignored as authority. Unknown and unauthorized objects yield indistinguishable non-disclosing responses. Ownership is also applied before aggregate counts. No truth/research endpoint is registered in the clinician API. Avoid arbitrary artifact-path parameters; resolve opaque accepted artifact IDs to immutable manifests under an allowlisted root and verify hashes before use. A manifest hash alone does not authenticate its producer.

### Process and storage denial

Use separate unprivileged containers for generator, truth evaluator, service and learner/analysis worker. Generator and evaluator can read the evaluator-owned parameter/equation manifests; API/UI/learner images exclude `simulation/`, `evaluation/truth/`, DGP parameter tables and truth artifacts. They may receive nonsecret version/hash identifiers, never structural values or latent paths. Copy only needed domain modules into consumer images; test imports do not transitively import evaluator-only modules. No application container receives Docker socket, host root/repository mount, privileged mode, host PID namespace or truth-volume mount.

Generator writes truth to a private named volume and schema-validated observed exports to a distinct staging volume. A bounded export validation step admits only typed observed records/manifests to an immutable observed volume mounted read-only by learner and read-only by the service importer. The service's database volume is separate and writable only by its service identity. Evaluator reads observed artifacts and private truth; writes labeled research reports to a third restricted output. Never serve that volume through frontend static hosting. Drop capabilities, forbid privilege escalation, keep root filesystem read-only with bounded temp storage, and restrict internal network connectivity. Host administrator remains trusted; this boundary protects application identities, not a hostile host administrator.

Acceptance probes run **inside the actual API and learner identities**: direct file open/list of truth volume, import of evaluator modules, network connection to evaluator, forged truth fields, path traversal and static/debug URL attempts must fail. A private canary read succeeds under evaluator identity to establish the fixture exists. Check mounts/UIDs and HTTP response bodies/logs; deny-by-field-name alone cannot pass. Foundation can use a synthetic canary before generator exists; G1-GENERATOR repeats denial against real generated truth. Export tests must also show raw source payloads, logs and build assets contain no privileged fields.
