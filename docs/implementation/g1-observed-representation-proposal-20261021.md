## 2. Versioned wire proposal (OBS-REP-02, version 2.0.0)

Keep all v1 parsers, schema URNs, dictionaries, fixtures, historical envelopes and hashes reproducible. Introduce a separate observed profile rather than changing `Versioned.schema_version` globally. New DailyReport/support record shapes use `schema_version="2.0.0"`; unchanged kinds retain their existing v1 shape. New v2 history/learner/export/replay/run wrappers dispatch explicitly by `(schema_version, kind)`; a kind-only discriminator is insufficient for two DailyReport versions. Unknown combinations fail closed. No v1 record is silently upgraded or interpreted under v2 semantics.

Every new record retains the exact Record provenance fields, strict finite numerics and `event_at <= recorded_at <= available_at`. Preserve same-event, same-kind correction lineage, unique IDs/revisions, duplicate raw-source identity and tombstones. Cross-version corrections are disallowed in this profile: migration creates a separately identified derived artifact with its source references, never edits a predecessor. For all links below use an exact record reference `{record_id, payload_sha256}`; resolve in the same patient/run partition and verify type/hash. Lineage IDs may additionally describe a logical series but cannot replace exact references.

### Diary

`DailyReportV2` has the v1 fields and missingness rules, with finite signed `diary_sleep_minutes` in **minutes**, unbounded on both sides. Its intrinsic channel is patient-reported diary, never wearable or latent true sleep. Negative and >480 values remain observed numeric values. The source registry declares a dedicated diary-report source identity with adapter `patient_report`; the existing generated source version remains DGP `1.2.0`, while the new representation binding identifies this wire profile. Sleep quality/function retain 0–10 bounds; burden remains the old nullable scalar until a separately accepted typed rating definition exists. New G1 generated reports leave this ambiguous scalar null and use explicit outcome links below for any defined support measure.

TIME-01 v2 remains unchanged: prior-night event 07:00, recording decision 08:01, delay from recording, equal-time cutoff exclusion. Missing/pending reports contain no numeric values. Observed reference reports carry the diary draw in this field; setting it null and emitting an untyped diary Observation is invalid for this profile. Missingness fixtures preserve the same observation law. Do not add a second diary likelihood, clip values, reject finite tail values, censor extremes, or replace them with missing. Wearable clipping and device semantics remain separate. No post-death symptom report is generated.

### SupportDecision (new kind `support_decision`)

Required fields beyond Record:

- `decision_snapshot`: exact DecisionSnapshot reference; `decision_index`: nonnegative index in the run's scheduled support roster; `cutoff`: aware instant equal to snapshot cutoff; `context`: exact references to the active observed records actually used; `context_projection_sha256`: canonical complete learner projection at cutoff; `context_mapping`: VersionRef describing the policy feature transformation.
- `policy`: VersionRef for the complete executed support mechanism, matching snapshot.workflow.support_policy, including fixed/frozen mapping and burden behavior; `mode`: fixed/mrt/adaptive/frozen/paused matching the snapshot. Approximation settings/error for an adaptive mechanism must be supplied by that policy's separately accepted contract before execution; no invented G1 defaults.
- `eligibility`: exactly one status/reasons entry for each of `support_prompt`, `no_prompt`, agreeing with the snapshot; `availability`: `unavailable | deterministic | randomized`; `unavailable_reasons`: nonempty only for unavailable; `probabilities`: both action keys, finite values in [0,1], the **post-mask, post-bound, normalized executed distribution**; `assignment_id`: preallocated Assignment ID or null. The completed partition binds that ID to its exact payload hash through RecordBinding; this one forward link uses an ID so its decision can be persisted before the draw.
- `outcome_window`: `{id, starts_at, ends_at, assessment_at, timezone, local_date, endpoint_definition}`. Half-open window [starts_at, ends_at), start at this support decision; assessment_at is the following morning 07:00 and equals ends_at for the current daily protocol. Endpoint definition is a VersionRef naming next-morning sleep quality and its units/direction. Only one scheduled decision per patient/window; preserve day/zone identity rather than infer a calendar join.

Unavailable means eligible set empty, both masses zero, no draw/assignment/delivery; the zero vector is explicitly **not** a probability distribution over a randomized no-prompt action. Deterministic means one eligible action, mass one there and zero elsewhere. Randomized means both eligible, sum one and each within accepted [0.1,0.9] bounds; use the same validated numeric distribution for sampling and logging. A fixed policy may make only its approved action eligible after all constraints, with its reasons retained. Do not convert an infeasible two-action configuration into a deterministic policy to conceal a failed bounds check. Probability sum validation uses the serialization/normalization tolerance fixed by the implementation contract, records that tolerance, and cannot relax the action bounds.

Persist decision/distribution before drawing. Assignment then links back via its existing `decision_id` to the same snapshot; SupportDecision's preallocated assignment ID must resolve in the completed export, or the partition remains partial. No circular payload hashes: Assignment references snapshot ID, not SupportDecision hash; the archive manifest binds both exact payloads. Assignment option/policy/patient and selected propensity must match. Existing experimental MRT metadata is required for randomized rows; deterministic ordinary fixed assignments retain `experimental=false` and null probability/seed, with probability one stored in SupportDecision. No randomization is implied by a deterministic row. Overrides remain on Assignment and delivery remains separately linked; never rewrite the executed distribution to compliance probability.

A complete roster includes unavailable points throughout the declared observation horizon while alive, including holds/admission; after death no support decision is defined. Record that terminal roster truncation against the death event instead of inventing missing decisions. Before a partition's receipt cutoff, future decisions are absent, not unavailable. Decision facts finalized after their cutoff cannot become their own predecision predictors.

### SupportOutcomeLink (new kind `support_outcome_link`)

Required fields beyond Record: `support_decision` exact ref, `assignment_ref` (null iff unavailable), `window_id`, and `reward` containing `status=observed|pending|missing|undefined`, exact DailyReport ref or null, `field="sleep_quality"`, `unit="quality_points"`, and a nonempty reason for non-observed states. An observed reward requires an observed report with a nonnull quality value at the specified assessment; store the value only in that report. References cannot point to another patient's/window's outcome. Undefined records a terminal/estimand reason; no report is fabricated after death. Unavailable decisions may link a genuinely collected report for descriptive history, but are excluded from randomized contrasts and never equated with missing reward.

`burden` is a list of typed entries `{definition: VersionRef, type, unit, status, value, source_refs}`. Initially allow only `offered_prompt_count` and `delivered_prompt_count`, unit `count`, nonnegative integers derived from unique linked Delivery events with the corresponding stage and prompt option; record separate counts, not their sum. The definition specifies deduplication by assignment/stage/window and requires complete observation of that stage before an observed zero is valid. Otherwise mark pending/missing with null value. These are operational exposure counts, not patient ratings, tolerability or a substitute for the existing policy's cap calculation. No-prompt is not a delivered prompt. No numerical patient-reported burden entry is permitted until its scale, time window, measurement/reporting law and source mapping are independently accepted. Distal ISI remains a separate assessment and estimand; this link does not copy ISI into reward or invent a composite utility.

Each update to pending/missing/observed outcome linkage is an append-only same-assessment lineage revision, with later recorded/available times; dependent report correction/retraction requires a newly validated link revision. Preserve the earlier link and report for earlier cutoffs. At a consumer cutoff, an exact ref that is superseded/retracted or not yet visible cannot silently resolve to its replacement: report the link unavailable/stale until a visible revised link resolves. Different consumers must not count both report and linkage as independent observations. Delivery counts and availability are observed policy facts and may contribute the appropriate factual-assignment/receipt information to the independent evaluator; they are not latent outcomes.

### Independent hold mapping, using existing types

G1 explicitly needs holds independent of admission: accepted DGP decisions include L-threshold review, adverse symptoms and clinician concern. For every enter/change-reason/resolve transition, emit an immutable DecisionSnapshot at the **effective transition event time**, with actual recorded/available times, fresh lineage ID, increasing patient/state/eligibility versions, clinical state and full reasons. It is not a correction of an earlier decision. Persist an initial baseline snapshot so interval state is defined. Same-instant transitions use increasing state_version, then stable record ID for replay; contradictory equal-version states are invalid. Corrections revise the same transition lineage, not the whole subsequent timeline.

Hold entry has `clinical_hold`, nonempty reasons, paused support and all experimental actions excluded. Resolution is an explicit later `assessment` snapshot, not disappearance of reasons, discharge alone, expiration of a timer or absence of an Assignment. Existing immutable decision-bundle composition stores predecessor snapshot reference, trigger/review record references and hashes, observed context and transition reason; a v2 export validates this bundle as read-only evidence. Use real observed IntercurrentEvent values for fever/confusion/fall/admission/regimen changes where present; never relabel a hold as admission. Encounter.review_status may corroborate but cannot alone establish transition reason/time. Snapshot posterior may be null; bind an explicit no-estimator model configuration rather than fabricate fitted evidence. Simulation source/actor labels must state simulated review, not a live clinician identity.

A reason may state a generated threshold-trigger fact without exporting hidden L coordinates or privileged latent values. The independent evaluator must retain the corresponding threshold/eligibility likelihood information; no hidden state becomes a learner covariate. The trigger history and snapshot record the observed fact that a hold occurred, not its unobserved numeric cause.

There is no new clearance-time distribution or automatic resumption rule here. If a scenario requires clearance not already fixed by an accepted protocol/script, that transition and dependent resumed trajectories remain blocked pending a separately sourced decision. Admission's configured seven-day course does not authorize clearing other holds or current clinical review. This restriction preserves [ASSIGN-09](workflow-contract.md) and explicit re-entry through assessment.

## 3. Archive, live authority and compatibility

Current [ReplayBatch/verify_partition](../../contracts/runs/observed.py) accepts raw bytes only for INGESTIBLE rows; administrative records are in history but excluded from ReplayBatch. Thus the Luna shorthand that administrative raw replay is already preserved is insufficient. V2 replay must include **every history record**, including snapshots, consent, approvals, assignments, delivery, support records and transition bundles, with original UTF-8 raw-source bytes and canonical payload hashes. Validate each against its version-specific typed original. Keep exact source bytes; duplicates retain the original payload convention. RecordBinding still states the route. Administrative raw bytes are evidence, not commands.

V2 separates `archive_only` from `clinical_observation_import` by a trusted kind/origin allowlist, never by an uploader's assertion. Support decisions/outcome links, snapshot bundles, approvals, assignments, delivery and **all generated consent/oversight records** are archive-only with explicit exclusion `administrative_event_not_live_authority`. Ordinary symptom/observation/intercurrent facts may enter the existing event store under ownership and admission rules; known safety facts can invalidate current readiness. A simulated resolved snapshot cannot clear a current hold. Imported active consent cannot grant consent or oversight, and imported approval cannot authorize drawing. Generated withdrawals remain visible historical facts; any live revocation follows the authenticated service workflow, not a generated grant path.

The v2 importer validates and retains the full archive but passes only the allowlisted clinical subset to foundation replay; ownership must already exist. Never pass archive entries wholesale to `replay()`. Keep current safety's inclusive arrival invalidation separate from strict learner cutoffs. Live clinician updates retain authentication, ownership, optimistic versions, CSRF, explicit resume and atomic rollback/idempotency checks. Legacy v1 archive parsing/reproduction remains available; a legacy generated artifact cannot bypass these current authority guards merely by selecting v1. Historical authorized records are displayed with their original provenance and versions, not rewritten as v2 clinical actions.

New run/export/evaluator-request bindings include `observed_representation: VersionRef(OBS-REP-02,2.0.0,accepted-spec-hash)` and exact domain/run schema-set hashes. Scientific bindings retain the existing DGP1.2.0, TIME-01 v2 and protocol/precision identities. Use separate bindings-v2.json and dictionaries/schema URNs under v2 paths. Preserve bindings-v1.json and old generated products byte-for-byte. The profile is an explicit supplementary representation dependency, not global relabeling of the old G1 plan. New manifests/results/authorities bind the chosen representation and exact hash; no acceptance of a v1 fixture as a v2 producer run. Derived migrations have new artifact/run IDs and both source and transform provenance. V1 data lacking full propensities or burden attribution remains insufficient for those analyses; never infer missing fields from today's policy.
