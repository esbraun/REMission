# LIVE-HOLD trigger binding supplement — proposed, unaccepted

This bounded shared-shape supplement implements the already accepted R1 per-trigger authority semantics. It is proposed for separate independent critique before dependent source changes. It adds no scientific clearance, burden, threshold, duration, freshness, resumption or clinical urgency law. Source checkpoint `c6e3adca7adda5eb19833ee28ce468777172ff38`, accepted base `ec18cb4020ba239710a3fd615e365d5cd72b4d80`; assigned Sol/xhigh as recorded in the implementation evidence.

The implementation's initial SourceGrant flattened all trigger rules and required reviews plus one due time. A valid exact package can contain enter/change transitions with different trigger rules, requirement subsets and follow-up times. Requiring each bundle to equal the whole flattened grant rejects that valid package. A mixed episode must retain every unresolved obligation, while missing threshold rules must still block its entire clearance. Existing task IDs and old migrations cannot be rewritten.

Proposed initial service-1.0 configuration shape, before any independent implementation acceptance:

* Keep SourceGrant's exact actor/owner/service/archive patient, source/run/partition, archive/package/authority digest, ownership ref, episode namespace and allowed operation fields.
* Replace its flattened `trigger_rules`, `required_reviews`, `follow_up_owner_id`, `follow_up_policy`, `due_at` and `escalation_destination` with nonempty `trigger_bindings`.
* Each TriggerBinding is `{trigger_rule: VersionRef, required_reviews: nonempty list[Requirement], follow_ups: nonempty list[FollowUpBinding]}`. Requirement retains its exact ID/definition, doctor role, evidence kinds and permitted sources. Each FollowUpBinding is `{reference: ExactRef, owner_id, policy: VersionRef, due_at: aware datetime, escalation_destination}`. No implicit default or computed interval exists. Exact per-package source follow-up refs and due times are administratively installed; overdue dates remain overdue.
* Reject duplicate exact grant keys (including archive/package identity), duplicate trigger rules in a grant, duplicate requirement IDs with conflicting content and duplicate follow-up refs with conflicting content. A shared requirement ID must have the same full definition/role/evidence constraints wherever used. All configured follow-up owners must equal the authenticated owning doctor. Configuration installation validates these invariants and digests the complete new shape.

Invalidation resolves every exact positive trigger from the whole verified bundle. Every trigger rule must match exactly one installed binding; its declared requirement VersionRef must be among that binding's exact requirements. The union of matched bindings' requirement IDs/definitions/roles must equal the bundle's required_reviews, without omission or substitution. Every matched binding's exact follow-up must resolve and appear in both the relevant trigger's and bundle's follow_up_refs. Conversely, each bundle/trigger follow-up must have an exact matched installed binding; no extra ungranted follow-up is accepted. Other archive baseline/resolution tasks do not become live tasks. Every such record and closure remains in the same exact source package/run/partition/patient/episode scope under current committed access rules.

For an active episode, append the newly matched complete requirements to its unresolved union. Never remove a previous requirement/reason/trigger or replace its definition through strengthening. A conflicting definition rejects the entire transaction. Absence of a manual criterion for any active trigger/obligation leaves whole-episode clearance unsupported. A concern rule cannot satisfy a threshold item. Pending mixed review remains recordable with every obligation explicitly present; whole-episode satisfied is unavailable until every exact item has an accepted rule and required evidence. No change to observed v1/v2 or their product bytes is proposed.

Create a separate immutable owned live review task for each distinct matched configured follow-up binding in the episode generation. Derive stable task identity from episode ID/generation and full exact follow-up binding (including policy/owner/due/escalation and source ref); a repeated transition/retry does not duplicate it. Store all `task_ids` in the episode payload and expose all owned tasks in the current episode view; remove the implementation-only singular task_id field before initial acceptance. Strengthening appends task IDs and pending events; it does not rewrite old task rows or silently advance overdue dates. Review retains all tasks/holds. Explicit clearance closes every task in that episode generation, and no other episode's task. Receipts already define plural task_ids and report the complete generation task set. Current UI shows each owner's exact due time and status without a default selection or countdown. No old migration changes; new table columns are unnecessary because episode/task payloads already carry these facts.

Generation cutover retains all old unresolved obligations/tasks and adds only bindings matching the episode's recorded source namespace/run/partition and active trigger rules. It may add an explicit new configured task as part of the audited authority change; it cannot weaken/substitute definitions or reset existing due times. Removed grants/criteria leave requirements unsupported. One patient/state/eligibility increment per held patient, consent unchanged, regardless of task count. The authority_changed fact retains the complete resulting obligation hashes, invalidates reviews, and does not clear latches. Current source-package authorization remains mandatory before new invalidations or receipt aliases.

Required focused counterexamples: two transitions in one package with different requirement subsets and due dates; two positive rules within one mixed-reason episode; duplicated/mismatched rule/requirement/task refs; unconfigured extra follow-up; omitted earlier obligation; stronger later obligation; concern satisfied + threshold pending cannot clear; exact replay has zero delta/new tasks; semantic cross-key retry returns original receipt; multi-episode clearance closes only selected generation tasks; earlier overdue task survives later strengthening; revoked rule/grant and authority rollback retain unresolved tasks/obligations; archive/raw/v1/old ledger bytes unchanged. Whole-package failure publishes no archive cursor, clinical facts, tasks, operations, keys or versions. Browser rerun must cover the changed multi-task view and mixed review controls after code/image binding.

This proposal is not permission to install any new scientific criterion. Implementation waits for an independent ready disposition on this exact supplement; unrelated accepted product/fault/compatibility work continues.
