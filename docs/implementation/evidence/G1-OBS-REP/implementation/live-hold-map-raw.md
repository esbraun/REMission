## Requirement-to-seam map

- **Authenticated, owned patient:** primitives exist in `session`, `own`, and mutation CSRF checks. A new route must bind the authenticated service patient/owner itself; the current ingestion's caller-supplied record patient is only checked for equality after ownership is established.
- **Source-authorized exact accepted trigger/bundle hashes:** missing. V1 intake verifies declared raw hash and typed payload equality, but no trusted accepted-hold authority, exact bundle/snapshot reference validation, per-source authorization, or archive receipt is present.
- **Actual live receipt time and inclusive invalidation:** partially present for ordinary safety events: `append_event` rewrites availability to actual receipt, and current safety is inclusive. Missing for independent holds because no accepted bundle/trigger path feeds that function and no durable latch survives later event projections.
- **Atomic latch, readiness/version invalidation, pending owned review, audit/idempotency receipt, cursor:** pieces exist separately (patient version updates, `pending_work`, `state_changes`, `ingestion_receipts`, replay cursor; migration lines above), but there is no hold operation composing them atomically. Existing live-ingest receipt is generic; replay cursor is archive replay state, not hold receipt cursor.
- **Existing approvals and concurrent stale writes:** approval compares four current versions and transaction serializes writes; race coverage exists for ordinary hold state change. New latch must advance the versions/readiness state in the same transaction so a concurrent approval cannot commit against the prior readiness. Current generic `ASSIGN-09` route is not linked to an accepted independent-hold trigger.
- **Latch survives generated resolution, correction/retraction, consent, or imported approval:** no latch exists. Current safety resolves latest visible lineage heads, so correction/retraction can remove a supported event from current safety. `state_change` can then move back to an ordinary stage. Current export replay cannot import admin approval records through v1 `INGESTIBLE`, but there is no complete v2 archive-only/import guard or separate live-hold receipt.
- **Clinician review/clearance:** authentication and optimistic versioned state mutation exist, but no evidence-checked clear operation. The state endpoint accepts arbitrary stage changes and reason text, with no required reviewer role, current hold version, assessment snapshot, evidence refs, or resolution chain. The specific required live clearance workflow is therefore unsupported and remains blocked.
- **Immutable as-known history vs current readiness:** immutable event/bundle/decision persistence and strict as-known projection exist. These preserve what was saved at the time, while current readiness is recomputed from current workflow and visible safety heads. A later hold must create a new version/decision and retain prior snapshot/display bytes; it cannot rewrite historical saved views. Existing tests validate strict learner equality boundaries and preserved historical bundle display, but not hold-transition reconstruction.

## Blocker status

The base contains reusable auth/ownership, version guard, transaction, audit, receipt, current-safety, and immutable-history primitives. The concrete missing integration is an authenticated source-authorized independent-hold admission path that validates accepted hashes/provenance and atomically records actual arrival, durable safety latch/readiness invalidation, versions, owned pending review, audit/idempotency receipt and cursor. It also lacks an evidence-gated authenticated clearance workflow. Until that route and its real service evidence are implemented and independently accepted, the accepted plan's `independent_hold_live_integration_required` precondition remains unmet; archive rejection or ordinary `ASSIGN-09` tests do not accept live hold behavior or affected current replay/full G1 demonstration.
