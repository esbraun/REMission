## Actionable findings

### P2 — Strict CSV boundary accepts uncontracted fields and missing patient identity, then invokes the worker

Locations: `contracts/artifacts/manifest.py:143`, `:150`, `:164` and `:197`; regressions in `tests/library/test_artifacts.py` do not cover these compositions.

`csv.DictReader` preserves surplus body fields under the `None` key. The validator checks header names but never rejects those fields. Consequently a correctly hashed draw payload with header `chain,draw,quantity,value` and body `0,0,mu,1.2,uncontracted` passes a one-chain/one-draw manifest and reaches the worker. The same occurs with an extra field after the eight WCLS columns. These are not forged checksums: the manifest legitimately hashes the malformed payload, which is precisely when semantic validation must reject it.

The WCLS path also accepts an empty `id` in an otherwise valid row. That is not a valid independent patient identifier. The returned record can silently create an unidentified cluster or merge unrelated blank-ID records when downstream analysis groups by patient. All three adversarial cases returned `done` with `worker_calls 1` through `dispatch_checked`. Malformed UTF-8 was correctly rejected with `worker_calls 0` in the same test harness.

Reproducer: ignored `adversarial.py`, result `adversarial.log`. It constructs valid manifests using the existing test fixtures, changes the payload bytes, updates the matching SHA256 and calls the real public dispatcher. It does not bypass Pydantic or monkeypatch validation.

Required fix: validate each CSV row's exact arity/keys, reject missing fields, and enforce the declared nonempty patient identifier contract before returning usable WCLS records. Retain valid arbitrary identifier strings permitted by the chosen contract; do not accidentally coerce IDs into numbers. Add rejection tests for both formats' extra/short rows and missing/invalid patient identifiers, through dispatch with zero worker calls. This repairs the existing narrow format contract rather than introducing a broad CSV framework.

### P2 — Actual WCLS fixture manifest misidentifies its producer and input lineage

Locations: `tooling/library/probe-python.py:86`, `tooling/library/probe-offline.R:61`, `tooling/library/qualify-exchange.py:23–44`, committed `exchange/wcls-input.csv.manifest.json`.

The WCLS input CSV is generated by Python from the explicit deterministic patient/time formula. R reads it and fits the reference model. However, the manifest generator applies one common R producer and one common input list to every artifact. The WCLS input manifest therefore records the R image/runtime as producer, identifies the unrelated normal-normal `fit-input.json` and `pymc-draws.csv` as inputs, and hashes `probe-offline.R` for every source/model/prior/transform reference. Neither the WCLS input formula nor its Python producer is represented by that lineage. A changed WCLS-generating Python script can leave all those named input/source hashes unchanged.

The numeric WCLS comparison is real and independently reproducible; this finding concerns the LIB-03 provenance claim, not its coefficients. Hash-valid files and complete-looking metadata are insufficient when the metadata describes the wrong producer. Likewise, mixture files are constructed from a fixed R prior definition, not causally from the PyMC draw inputs listed by the common helper. Their actual definition/source needs explicit representation rather than unrelated shared inputs.

Required fix: emit artifact-specific producer, source and direct input lineage. Identify the Python WCLS generator/fixture definition and actual runtime for the CSV, and separately identify the R analysis/returned result. Preserve original input/return hashes through the R bridge. Identify R mixture recipe/source independently of PyMC draws. Use explicit fixture version references whose hashes cover the named definitions; a complete script hash is acceptable when accurately described. Regenerate the affected manifests and rerun validation/roundtrips. Add a lineage regression demonstrating that changing the generating definition changes the appropriate recorded version/hash. Do not relabel the current files as clinical/model qualification.
