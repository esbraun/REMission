## R offline toolchain source leads

- **CRAN release/binary records:** RBesT and MRTAnalysis CRAN records link source packages and current `r-release`/`r-oldrel` Windows/macOS binaries. A package binary listing is not evidence that its complete dependency chain installs or runs in the target environment.
- **R on Windows:** CRAN’s official [Rtools matrix](https://cran.r-project.org/bin/windows/Rtools/) currently lists Rtools 4.5 for R >=4.5.0 (including R-devel), 4.4 for R 4.4.x, 4.3 for R 4.3.x, and 4.2 for R 4.2.x. It does not show a dedicated Rtools 4.6 entry on the inspected page. The current [R Installation and Administration manual](https://cran.r-project.org/doc/manuals/r-release/R-admin.html) identifies its release as R 4.6.1 (2026-06-24), so the exact supported Windows source-build pair for a chosen R 4.6.x must be reconciled rather than inferred. RBesT’s CRAN record requires C++17, GNU make, pandoc >=1.12.3, and pngquant, and says compilation is needed.
- **Unix/Linux and macOS:** the CRAN [R Installation and Administration manual](https://cran.r-project.org/doc/manuals/r-release/R-admin.html), sections “Installing R under Unix-alikes,” “Installing R under macOS,” and Appendix A, is the authoritative general toolchain lead. It describes C/C++/Fortran compiler and system-library prerequisites and platform differences; RBesT’s C++17 requirement and Stan/Rcpp dependency chain make a complete compatible compiler, Fortran/BLAS/LAPACK and native-library environment a package-specific qualification item. MRTAnalysis declares no compilation itself, but imported dependencies may compile.
- **Scope rule:** all three R tools remain offline CLI/artifact workers, never dependencies of Python/FastAPI request handling (`sw-rbest`, `sw-sbc`, `sw-mrtanalysis`; canonical `LIB-01`). No R installation or compile probe was performed here.
