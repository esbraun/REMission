# TA2-SE result-admission and scalar-reader source map

Public source-only map at source base/head `9292844a46aa4ba46701c9bb45cd703f0862dee6`, branch `docs/poc-ta2-se-admission-map-20261024`. No tests/imports/computation, app/Store/runtime, or artifact payloads were opened. Accepted plan `b97296f43598fb9d2cff2473a4910dc9c1d999bb` and different critique `f41b34efed3d7e3fd08dac846e3fc5e8886d95f5` are read as bounded public text only.

The accepted scalar is the fixed implemented V0/V1 point estimator across planned independent cohorts, for one frozen scenario/ordinal/cutoff and declared successful-pair set. The plan's prose calls the value `result.member[j].effect.mean`; the current app contract actually exposes a `CohortResult.patients` list. In source, use the manifest's patient identity/history binding to locate `patients[j].effect.mean`; do not assume a `member` field exists. The critique explicitly requires whole-cohort admission before scalar selection, all member/chain/estimand diagnostic gates, and discarding every partial member effect when a joint result fails.

The minimum handoff to the Sol implementation is therefore the existing path `analysis.ingest` → `cohort_analysis.validate_result` → persisted typed `CohortResult` → `appointment.checked_result`/`cohort_analysis.comparison`. The current restricted truth request path does not admit TA2 restricted truth. This map confirms no scalar-only qualified reader in the inspected files; the bounded adapter question is where to take the member scalar after accepted stored JSON, while retaining whole-result gates. It does not assert any current fit/truth acceptance or add/change requirements.
