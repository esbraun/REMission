# Rendered-app bootstrap admission regression

Run these browser recipes through the official Playwright MCP tools against the own isolated8771 deployment. They use the actual built React app and actual server session/admission gate. They are not Node helper tests, a CLI browser replacement, intercepted network responses or a claim that a copied-image build executes the browser. The supporting Node context test only checks epoch semantics.

1. Bind exact source/image/assets and log in as public fixture Alice. Create an active SYN02 concern with the visible configured concern control; record the owned session cookie and current held/unready workspace. Do not copy another deployment's database or cookies.
2. Start a separate process with an exclusive flock on this deployment's exact admission lock; observe its explicit READY barrier. Keep it held. Use a cold navigation to /patients/SYN-02/current with the valid cookie. Execute bootstrap-busy-start.js through official MCP. It observes bootstrap503 and presses the actual refresh button while the gate is still held, requiring a second503 request and no restored identity.
3. Explicitly release that holder, observe RELEASE and process exit. Execute bootstrap-busy-recover.js in the SAME page. It presses the visible refresh and requires exactly one new GET /api/session200, restores Alice and the current held/unready patient, and verifies empty local review/choice input. No full page reload or sign-in is allowed between the failed bootstrap and this recovery. The old801/47da implementation fails this schedule because its refresh makes zero session requests.
4. Repeat with an expired/revoked cookie: after RELEASE and visible refresh the session bootstrap may return an anonymous200; the actual sign-in form must remain, with no doctor/patient/local draft content. Reauthentication is explicit. Run the existing expiry/reauth/draft-clearing and stale-context browser cases against the new assets, including late results after identity change and ordinary authenticated busy-workspace refresh.
5. Preserve the full official raw sequence, actual browser metadata (MCP package version unavailable unless exposed), network statuses, desktop/narrow screenshots and UUID holder/setup command stdout/stderr with source/image bindings.
